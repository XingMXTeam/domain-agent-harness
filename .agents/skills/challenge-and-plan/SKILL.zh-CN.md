# Challenge and Plan（中文阅读版）

> 本文件为 `SKILL.md` 的中文阅读版，方便人类阅读与评审；Agent 实际执行的规范以同目录 `SKILL.md` 为准。

## 核心原则

面对非平凡需求、架构改造或 Issue 巡检时，**严禁直接改代码**，也不要默认用户提出的问题定义就是正确的。先穿透症状找到根因，再对齐偏好与约束，最后给出 3 版真正有取舍差异的方案供拍板。

## 执行步骤

1. **先分析再动手（禁止改代码）**：只读检查相关代码、日志或 Issue，明确影响面；此阶段严禁修改任何文件。
2. **挑战问题定义（别把症状当根因）**：判断需求是否把「症状当根因」或「手段当目标」，如果存在更高杠杆的底层问题，直接带证据指出来。
3. **先提问对齐喜好与约束**：提出 2–4 个高信息量问题（核心目标、持久化/隔离边界、基础设施与预算约束、时间窗口），等待用户回答。
4. **出 3 版不同取舍的方案**：按「最小止血 / 推荐平衡 / 全量重构」给出对比表（覆盖范围、取舍、风险、耗时、改动文件清单）与明确推荐。
5. **等待拍板后再动工**：用户明确选定方案前不写一行代码。

## 反模式

- ❌ 边“分析”边偷偷改代码。
- ❌ 盲从表层方案，不做根因校验。
- ❌ 没对齐偏好就硬给 3 个几乎雷同的假选项。
