# Repo Community Patrol（中文阅读版）

> 本文件为 `SKILL.md` 的中文阅读版，方便人类阅读与评审；Agent 实际执行的规范以同目录 `SKILL.md` 为准。

## 核心原则

仅在用户**显式启动**巡检或定时循环（如 `/loop`、`/schedule`）时执行，覆盖 GitHub Issues 处置、PR 逐行严审与本地实跑验证、以及社区频道（如 Discord）全频道跟进。

## 执行步骤

1. **GitHub Issues 处理**：
   - 逐条评估价值：值得做的推进开发/发版并附证据回复；不值得做的礼貌说明理由。
   - 遇到第三方中转站广告 Issue，统一礼貌回复「感谢关注，日后会出相关合作方案，敬请期待。」，严禁盲目接入第三方中转站。
2. **GitHub PR 逐行严审与本地实跑**：
   - 逐行审阅每个 PR 的逻辑与边界，必须拉到本地真实跑通测试，确认无 Bug 后才允许合并。
   - 严防未经实跑的低质 AI 生成 PR，发现问题给出具体清单并退回或关闭。
3. **Discord 全频道巡检（如已接入）**：
   - 逐个巡检每一个频道，不遗漏；有价值建议直接推进修复或立项，待确认项持续跟进。
   - 回复用户时必须使用真实的 `@mention` 通知对方，不能只打纯文本昵称。

## 反模式

- ❌ 未在本地拉取实跑测试就直接合并 PR。
- ❌ 未获用户显式巡检授权就擅自对外发帖、合并或关闭 PR。
- ❌ 在 Discord 回复时只打名字文本而不用真实 `@mention`。
